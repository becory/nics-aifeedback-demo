# 回饋資料總覽頁改版

## 背景

「回饋資料總覽」（`/feedback-overview`，`FeedbackOverviewPage`）目前是一排 8 個篩選欄位、流量趨勢圖、9 個「熱門流量」前 5 名面板，再加上活動記錄表。使用者提供手繪草圖（`docs/Image_20260929_103610_883.jpeg`），要求改成以「總覽 → 服務評分 → 回饋來源」為主的儀表板，並改寫篩選區。

釐清後拍板：

- **時間區間**照草圖：`近 7 天`、`近 30 天`、`近 60 天`、`自訂` 四個按鈕。
- **篩選**：左邊下拉選欄位、右邊輸入關鍵字，按「新增」後成為一個篩選條件；篩選條件以**清單**保存，可以疊加多個。草圖上的「所有服務 ▾」就是這個欄位選單。
- **既有區塊**：流量趨勢圖與「熱門流量」面板拿掉，**只保留活動記錄表**，放在最下方。
- **服務 × 評價的交叉統計**由後端新增端點提供，後端 spec 另寫（`aifeedback-portal` 的 `docs/superpowers/specs/2026-09-29-feedback-service-ratings-design.md`），前端依那份合約實作。

## 篩選

篩選區分兩列，中間以分隔線隔開：

```
時間區間：[近 7 天] [近 30 天] [近 60 天] [自訂]
────────────────────────────────────────────────────────────
⏷ 篩選器：[服務名稱 | 測試 ×] [＋新增]                  [× 清除]
```

第二列是兩欄 grid：左欄為篩選器（inline，隨內容換行），右欄為「× 清除」，**只有清單有值時才顯示**。

**所有變更都直接套用並重新查詢**，沒有「搜尋」「重設」按鈕。篩選條件一律**繼承目前的時間區間**；切換時間區間時，已加入的篩選條件保留。

### 時間區間

| 按鈕 | `from` | `to` |
|---|---|---|
| 近 7 天 | 現在 − 7 天 | 不帶（至今） |
| 近 30 天（**預設**） | 現在 − 30 天 | 不帶 |
| 近 60 天 | 現在 − 60 天 | 不帶 |
| 自訂 | 起始時間 | 結束時間（選填） |

- 點預設區間按鈕立即查詢；選中的按鈕為 primary 樣式，其餘 outline。
- 點「自訂」時，該按鈕原地展開為組合輸入框 `[自訂｜開始時間 - 結束時間]`（兩個 `datetime-local`，開始時間自動取得焦點，結束時間留空表示至今），**不改變目前的查詢區間**。**焦點離開整個組合框時**，起始有值且不晚於結束才套用並查詢；起始為空時開始時間輸入框標紅、並在自訂組合框下方以小字提示「請設定起始時間」並維持原區間（輸入起始後提示消失），起始晚於結束時同樣標紅開始時間，並在同一位置提示「起始時間不可晚於結束時間」、維持原區間；焦點在開始與結束之間移動不觸發查詢。點其他預設按鈕則收起組合框。開始與結束各自有清除（×）按鈕（有值時才顯示，清除後焦點回到該輸入框）；兩端互為界線：開始時間的選擇器以結束時間為 `max`、結束時間以開始時間為 `min`，手動輸入超出界線時仍由上述驗證擋下。

### 篩選器（inline）

四種狀態：

| 狀態 | 顯示 |
|---|---|
| 沒有條件 | `⏷ 篩選器：[＋新增]` |
| 新增中 | `⏷ 篩選器：[欄位 ▾ \| 關鍵字]` |
| 有條件、檢視中 | `⏷ 篩選器：[服務名稱 \| 測試 ×] [＋新增]` |
| 有條件、再新增 | `⏷ 篩選器：[服務名稱 \| 測試 ×] [欄位 ▾ \| 關鍵字]` |

- 「＋新增」點下後原地換成「欄位 ▾ | 關鍵字」組合輸入框（欄位預設「服務名稱」，關鍵字自動取得焦點）；欄位為「評價」時右半改為評價下拉（good／normal／bad，顯示 `ScoreConfig` 名稱）。
- **焦點離開整個組合框（blur）即完成新增並直接查詢**；焦點在欄位與關鍵字兩半之間移動不算離開。Enter 等同 blur；Esc 取消。關鍵字為空或與既有條件完全相同時不新增，只收起輸入框。
- 已加入的條件以 chip 呈現（`cf-filter-chip`：`欄位名 | 值 ×`），× 移除後直接查詢。
- 「× 清除」移除所有條件並直接查詢（不影響時間區間）。

**欄位**分兩組：

| 群組 | 欄位 | 比對方式 | 送出方式 |
|---|---|---|---|
| 服務 | 服務名稱、服務代碼、網域（`Service.host`）、組織（名稱）、服務代理（名稱或代碼） | 關鍵字**包含**比對、不分大小寫，比對對象是頁面載入的服務清單（`getServices({ currentUser: true })`，含組織／代理名稱） | 轉成符合的服務代碼集合，送 `serviceId=CODE1&serviceId=CODE2…` |
| 回饋資料 | 評價、裝置、來源國家/地區、Session ID | **完全相等**（後端的篩選語意） | 直接送對應參數（`feedbackRating`、`device`、`ipCountry`、`sessionId`） |

回饋資料這組取代原本頁面上的「評價」「裝置」「來源國家/地區」「Session ID」四個獨立欄位，改版後不失去這些篩選能力。

**組合規則**：

- **服務群組**：每個條件各自篩出一組服務，多個條件取**交集**（例如「組織 包含 資安院」＋「服務名稱 包含 問答」＝資安院底下名稱含「問答」的服務）。交集為空時不送出請求，直接顯示空狀態「沒有符合篩選條件的服務」。沒有任何服務條件時不帶 `serviceId`（後端依可見範圍取全部）。
- **回饋資料群組**：同一欄位多個值為 OR，不同欄位之間為 AND（與後端 `?device=A&device=B` 的語意相同）。
- 兩個群組之間為 AND。

### 網址（可分享）

已套用的篩選與活動記錄頁碼同步到 query string，複製網址給別人即可開到相同畫面：

```
/feedback-overview?range=custom&from=2026-09-01T00:00&to=2026-09-15T23:59&serviceName=測試&device=iOS&page=2
```

- `range`：`7d`／`60d`／`custom`；預設的近 30 天不寫出。`custom` 時帶 `from`（必要）、`to`（選填），格式同 `datetime-local`。
- 每個篩選條件是一個 key（欄位名，例如 `serviceName`、`organization`、`device`），同欄位多個值重複 key；讀回時依網址順序還原 chip。
- `page`：活動記錄頁碼，第 1 頁不寫出。
- **相對區間保持相對**：`range=7d` 的連結在對方打開時是「對方的近 7 天」；要固定日期請用自訂區間。
- 開啟頁面時讀一次網址；之後每次變更以 `replace` 寫回（不堆疊瀏覽紀錄）。不合法的值（未知欄位、`custom` 缺 `from` 或起始晚於結束、非數字頁碼）一律忽略、回到預設。

## 區塊與資料來源

以下全部使用同一組已套用的篩選參數（`filterParams`，含 `from`/`to`）。

### 總覽

| 卡片 | 主數值 | 副標 | 來源 |
|---|---|---|---|
| 總平均分數 | `overview.averageScore`，一位小數；`null` 顯示「—」 | 「較上期 ↑3.2」／「較上期 ↓1.5」／「與上期持平」；上期沒有可計分資料時顯示「上期無資料」 | 本期 `GET /feedback/overview`；**上期**另查一次 `overview`，`to = 本期 from`、`from = 本期 from − (本期 to − 本期 from)`，本期 `to` 未帶時以「現在」計算長度。其餘篩選條件相同。 |
| 好評率 | `good 筆數 ÷ 總筆數`，一位小數百分比 | 「共 N 筆 {good 的名稱}」 | `GET /feedback/top-columns?groupBy=rate` |
| 總回饋筆數 | `overview.totalCount`（千分位） | 「本期累計」 | 本期 `overview` |

- 差值 = 本期平均 − 上期平均，一位小數；上升綠色 ↑、下降紅色 ↓、差值四捨五入後為 0 顯示「與上期持平」（灰色）。
- 評價名稱（good／normal／bad 的顯示文字）沿用頁面現有做法：取 `ScoreConfig` 的 `name`，找不到時顯示原始值。

### 服務評分

**各服務平均分數**：`GET /feedback/service-ratings` 的 `averageScore`。

- 橫條圖，依平均分數由高到低排序（相同時依筆數多者在前），`averageScore` 為 `null` 的服務不列出。
- 橫軸固定 0–100（分數設定的上限），條長與數值成正比，右側顯示數值（一位小數，整數時不顯示小數）。
- 最多顯示 10 個服務；超過時卡片底部顯示「另有 N 個服務」。
- 服務名稱過長時截斷（沿用 `truncateLabel`），hover 顯示完整名稱與代碼。

**整體評價分佈**：`top-columns?groupBy=rate` 的各評價筆數。

- 環圈圖（good／normal／bad 三段，顏色沿用 `CHART_COLORS` 的評價色），右側圖例：色點、評價名稱、百分比（一位小數）。
- 百分比以筆數 ÷ 三種評價合計計算；不在三種評價內的值不列入（整體平均分數也不計這些值，兩邊一致）。

### 回饋來源

**各服務回饋數**：`service-ratings` 的 `ratingCounts` 與 `totalCount`。

- 依評價堆疊的橫條圖（good／normal／bad 由左至右，顏色同上），右側為 `totalCount`；依 `totalCount` 由多到少排序（後端已排序）。
- 各條長度以最大 `totalCount` 為 100%。
- 卡片底部為評價圖例。最多 10 個服務，超過時顯示「另有 N 個服務」。
- hover 單一段顯示「服務名稱｜評價名稱：N 筆（佔該服務 x%）」。

**主要裝置**：`GET /feedback/top-columns?groupBy=device`。

- 橫條圖，前 5 名（後端上限），依筆數排序，右側為筆數。
- 底部「共 N 種裝置類型」，N 為回應新增的 `distinctCount`；`distinctCount` 大於 5 時改為「共 N 種裝置類型，顯示前 5 名」。

### 活動記錄

沿用既有 `ActivityLogTable`，改為**後端分頁**（不再一次取 1000 筆在前端切頁）：

- 每頁 25 筆，換頁時呼叫 `GET /feedback?page=N&pageSize=25`（篩選參數同上），只取該頁。
- 總筆數與頁數取自同一組篩選的 `overview.totalCount`（`GET /feedback` 本身不回傳總數）。
- 頁碼顯示以目前頁為中心最多 5 個，兩側超出時顯示「…」；載入中停用換頁按鈕。
- 篩選變更時回到第 1 頁。活動記錄的載入與錯誤獨立於上方圖表，換頁不重新查詢圖表。
- `ActivityLogTable` 成為受控元件：`feedbacks`（當頁資料）、`page`、`pageSize`、`total`、`loading`、`error`、`onPageChange`。

## 請求

每次篩選變更（時間區間、新增／移除／清除條件）與首次載入並行送出：

1. `overview`（本期）
2. `overview`（上期）
3. `top-columns?groupBy=rate`
4. `top-columns?groupBy=device`
5. `service-ratings`
6. `feedback?page=1&pageSize=25`（活動記錄第 1 頁；之後換頁只重送這一個）

`interval` 參數不再需要（沒有趨勢圖），`overview` 不帶 `groupBy`。原本 9 個 `top-columns` 請求減為 2 個。

- 任一請求失敗：頁面上方顯示錯誤 banner 與「重試」（沿用現有樣式），各卡片不顯示部分資料，避免數字彼此對不起來。
- 載入中：整區顯示 `LoadingState`。
- 本期總筆數為 0：顯示空狀態「此條件下沒有回饋紀錄」，不顯示圖表卡。

## 元件切分

- `src/pages/FeedbackOverviewPage.tsx`：狀態（已套用條件、已解析的時間區間）、請求、組版。
- `src/components/feedbackOverview/FeedbackFilterBar.tsx`：受控元件（`value`／`onChange`），時間區間按鈕與自訂區間、inline 篩選器（chip、＋新增、組合輸入框）、清除。只在本地保存自訂區間草稿與新增中的輸入框狀態。
- `src/lib/feedbackFilters.ts`：純函式——篩選條件型別與欄位定義、服務群組條件 → 服務代碼交集、條件 → API 參數、時間區間與上期區間計算。**不含 React**。
- **圖表沿用 `src/components/feedbackCharts.tsx` 既有元件**，只擴充參數：
  - 統計卡：`SummaryStat`（`hint` 改為可放 React 節點，用於較上期的顏色與箭頭）。
  - 各服務平均分數、主要裝置：`HorizontalBarChart`（新增 `formatValue`、每列 `title` hover、`legendLabel` 預設不顯示——單一系列由卡片標題命名）。
  - 整體評價分佈：`DonutChart`（新增 `labels` 顯示 `ScoreConfig` 名稱；圖例改為右側「色點＋名稱＋百分比」；區段間 2px 白色間隔；只有一種評價時畫成完整圓環）。

- `src/api/feedback.ts`：新增 `getFeedbackServiceRatings`（`GET /feedback/service-ratings`）、`FeedbackTopColumns.distinctCount`；`sessionId` 篩選改為可多值（後端本來就支援）。
- 移除不再使用的 `TrafficChartSection`、`TrafficChart`、`TopStatsPanel`、`FilterChip`（dimension filter）與頁面上的 `STATS_DIMENSIONS`。

圖表維持既有的 SVG／CSS 做法，不新增圖表套件；評價配色沿用 `CHART_COLORS`（已通過 dataviz 調色盤驗證；normal 與背景對比偏低，由圖例文字與數值標示補足）。

## 測試

專案目前沒有前端測試框架；`src/lib/feedbackFilters.ts` 的純函式若導入 Vitest 則補單元測試，否則以下列情境手動驗證：

- 時間區間：三個預設按鈕立即查詢、送出的 `from` 正確且不帶 `to`；點「自訂」不改變查詢區間；自訂起始為空或晚於結束時擋下並維持原區間；切換區間時篩選條件保留。
- 篩選器：四種狀態的顯示；焦點在欄位與關鍵字之間移動不新增；blur／Enter 新增並查詢、Esc 取消；空關鍵字與重複條件只收起輸入框；chip × 與「× 清除」直接查詢；「× 清除」只在有條件時出現。
- 組合規則：多個服務條件取交集；交集為空時不送請求並顯示空狀態；回饋欄位同欄位 OR、跨欄位 AND 的參數正確。
- 總覽：較上期差值的正負與持平；上期無資料；好評率與總筆數。
- 圖表：各服務平均分數排序與 `null` 排除；堆疊條各段比例與總數；超過 10 個服務時的「另有 N 個服務」；主要裝置的 `distinctCount` 文案（≤5 與 >5）。
- 一般使用者只看得到自己組織的服務（服務清單與統計皆由後端限制）。
- `npm run build` 與 `npm run lint` 不新增錯誤。
